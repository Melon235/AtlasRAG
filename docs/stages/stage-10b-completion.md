## 3. Confirmed In-Scope Defects Resolved During Stage 10-B

1. **`B10-09-F01` (Startup unsuccessful fence-reset fail-closed window):**
   - *Cause:* When `CacheFreshnessBarrier.enforce()` failed or timed out establishing a fresh write fence on startup (`BYPASSED` while PG `marker=False`), Redis could still retain a pre-restart `T_old` token and `SessionQueryCache` only verified PG `marker` plus Redis `fence is not None`, trusting `T_old` during the `cache_recovery_interval_seconds` window before `recover_if_due()` rotated it.
   - *Fix:* `CacheFreshnessBarrier` now tracks `_state` and `_active_write_fence` (`active_write_fence` returns token iff `_state is CacheFreshnessState.TRUSTED`), `SessionQueryCache` enforces optional `expected_write_fence` callback (failing closed on both `lookup` and `prepare`), and `SharedResources.cache_freshness` + `build_default_business` bind `lambda: cache_freshness.active_write_fence` in production (`src/atlasrag/runtime/cache_freshness.py`, `src/atlasrag/services/cache/session.py`, `src/atlasrag/runtime/composition.py`, `src/atlasrag/runtime/production.py`).
   - *Regression:* Offline `test_ar6_freshness_lifecycle.py::test_ar6_04_canonical_pg_error_always_propagates_and_outage_startup_rotates_on_recovery` + live Redis proxy `test_b10_09_startup_fence_reset_failure_leaves_barrier_bypassed_and_blocks_old_fence`.
2. **`B10-04-F01` (CUDA device identity resolution mismatch in `validate_shared_resource_contracts`):**
   - *Cause:* When configured `model_device="cuda"`, real `QwenEmbeddingProvider` and `BgeRerankerProvider` resolve `identity.device="cuda:0"` (matching `candidate._validate_runtime` and `current_repair._device_matches`), whereas `validate_shared_resource_contracts` in `src/atlasrag/runtime/composition.py` demanded exact string equality `identity.device != "cuda"`, raising `ConfigurationError` on real builds.
   - *Fix:* Added `_device_matches(identity_device, configured)` in `src/atlasrag/runtime/composition.py` aligned with Stage 4/5 (`identity_device == configured` or `configured == "cuda"` with `cuda:[0-9]+`).
   - *Regression:* Offline `test_ar6_composition_contracts.py::test_ar6_07_shared_resource_identity_and_index_contract_mismatches_raise_configuration_error` + live Stage 10-B build tests (`test_b10_04_b10_05`, `test_b10_06`, `test_b10_07`, `test_b10_09`, `test_b10_10`, `test_b10_11`, `test_b10_12`).
