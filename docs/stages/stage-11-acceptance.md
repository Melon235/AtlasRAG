## 2. Verification Strategy Across Layers A–D

### Layer A — Offline Unit and Contract Tests (`tests/stage11/`)

- Executed under `make verify` and `make test-stage11` with zero Docker, network, GPU, or paid API dependencies.
- Uses existing fake providers and `ApplicationComposition.start(build_business=...)` / fake `ApplicationCoordinator`.
- Covers: `ServerConfig`, `QueryRequest`/`QueryResponse` validation, `SessionRegistry` capacity/TTL/in-flight deletion, `MaintenanceOperationRegistry`, `InvocationEventBus` projection/slow-consumer overflow, `auth.py` Host/Origin/CSRF/token/body-limit checks, `errors.py` mapping for all 15 `ErrorCode`s, CLI `argparse` & `httpx.MockTransport` contracts, and `ApplicationServerService` cancellation/settlement.

### Layer B — Real Local Transport Tests (`tests/stage11/test_real_server_transport.py`)

- Launches real `atlasrag serve` subprocesses bound to ephemeral loopback ports (`127.0.0.1:0` or `allocate_port()`), using an isolated temporary `HOME`/`XDG_STATE_HOME` (or injected lock/state path in test launcher hook) and fake business bundle.
- **Explicitly supplements ASGI `TestClient`** (never relying solely on `TestClient`) to prove:
  - Real TCP HTTP requests and SSE wire chunking + heartbeats.
  - Real abrupt TCP disconnect mid-query and mid-SSE stream -> `InFlightTaskRegistry` + `QueryLease` settlement.
  - Real paused socket reads (slow consumer) -> bounded queue eviction + intact `final` event.
  - Real `SIGINT` / `SIGTERM` / `POST /control/shutdown` exit codes (`0` clean, `3` lock conflict, `4` unsettled shutdown).
  - Real CLI subprocess calls (`atlasrag ask`, `health`, `status`, `sync`, `recover`, `stop`) against the running server.

### Layer C — Real Infrastructure Integration (`tests/integration/test_stage11_*.py`, `scripts/stage11_verify.sh`)

- Reuses the fail-closed `scripts/stage10_isolation.py` container/volume/port/DB/Redis/Milvus ownership discipline (or parameterized `stage10_isolation.py` / Stage 11 isolated runner) against ephemeral `postgres:17.8-alpine`, `redis:8.2.10-alpine`, and `milvusdb/milvus:v2.6.20`.
- Runs a real `atlasrag serve` process wired to the isolated endpoints with fake embedding/LLM providers (avoiding GPU/paid API requirements in CI).
- Verifies HTTP/SSE end-to-end queries, same-session Redis `HIT`, cross-session isolation, `POST /control/sync` invalidation, Redis outage bypass & recovery, `BLOCKED` recovery via `POST /control/recover`, and clean shutdown teardown (`remaining=0`).

### Layer D — Independent Review Gate

Before Stage 11 implementation can be marked ready for merge:

1. **Architecture & Boundary Compliance:** Verify `ApplicationComposition=1`, `ApplicationCoordinator=1`, `ApplicationServerService` FastAPI-independence, zero MCP premature code, zero RAG semantic changes, `check_import_boundaries.py` pass.
2. **Lifecycle & Concurrency Correctness:** Audit HTTP/SSE disconnect task settlement, Uvicorn `timeout_graceful_shutdown` vs `coordinator.shutdown()` alignment, lock retention on unsettled shutdown, and launcher PID verification.
3. **Security Audit:** Audit Host/Origin/CSRF/body-size middleware, `0o600` `control.token` generation/validation/non-exposure, loopback enforcement.
4. **Cache Correctness Audit:** Audit `QueryCacheStatus` truthfulness, `CacheFreshnessBarrier`, Lua fence preservation, session ID safety, zero secondary answer cache.
5. **Real-Infra Isolation & Evidence Audit:** Audit zero impact on `deploy/local/.env` / dev volumes, `make verify`, Layer B & C test outputs, and `12/12` Stage 9 artifact integrity.
