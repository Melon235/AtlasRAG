## 2. Verification Strategy Across Layers A–D

### Layer A — Offline Unit and Contract Tests (`tests/stage11/`)

- Executed under `make verify` and `make test-stage11` with zero Docker, network, GPU, or paid API dependencies.
- Required negative coverage includes all 7 closure cases:
  1. Server removes `server.json` while original `stop` operation is waiting.
  2. New server starts immediately after old `ownership.release()` without old-server cleanup deleting new server metadata/token.
  3. Original PID disappears without clean-shutdown receipt (`shutdown-<id>.json`).
  4. PID identity mismatch (`starttime` / `boot_id`) or unavailable `pidfd` refuses escalation.
  5. Unresolved worker prevents actual process exit while retaining `RuntimeOwnershipLock` and refusing clean receipt.
  6. Repeated outer cancellation during worker settlement + concurrent disconnect/timeout/shutdown cancellation races.
  7. Maintenance `on_draining` admission callback failure + reservation-to-`DRAINING` cancellation/shutdown races.

### Layer B — Real Local Transport Tests (`tests/stage11/test_real_server_transport.py`)

- Launches real `atlasrag serve` subprocesses bound to ephemeral loopback ports, using an isolated temporary `HOME` state directory and fake business bundle.
